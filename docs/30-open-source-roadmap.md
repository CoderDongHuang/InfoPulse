# InfoPulse 开源优化路线图

## 当前基线

截至 2026-08-08，项目已经具备本地开源使用所需的代码、配置模板、MIT 许可证、安全披露流程、贡献指南、CI、CodeQL、Dependabot、Docker Compose、数据库迁移和两个 SDK。当前发布判断是“可以开源供开发者试用和贡献”，不是“所有第三方集成都已在任意环境完成生产验证”。

已验证基线：

- 后端 154 项自动化测试通过。
- 353 条 API 路径契约通过。
- Alembic 阶段 13 至 29 往返迁移通过。
- 前端类型检查和生产构建通过。
- Docker Compose 配置解析通过。
- TypeScript SDK 编译及打包预检通过。
- 前端离线依赖审计未发现已知漏洞。

## P0：开源发布后 0-4 周

目标是让陌生开发者在 30 分钟内成功运行，并让安全问题有稳定入口。

- 增加最小化 Docker Compose profile，默认不安装浏览器和重型多模态依赖。
- 为注册、登录、刷新令牌增加 Redis 限流、失败计数和 refresh token 单次使用撤销。
- 在干净 Python 3.10/3.11 环境执行 `pip-audit`，生成 SBOM 并上传 CI artifact。
- 增加 Linux、Windows 的快速启动 smoke test。
- 增加 Issue 模板、Pull Request 模板和功能演示数据初始化命令。
- 为核心页面补充 Playwright 无障碍与移动端回归。

完成标准：新环境安装成功率可量化；默认配置不暴露高危接口；CI 能检测依赖漏洞、契约漂移和基础 UI 回归。

## P1：1-3 个月

目标是提高真实链路稳定性和开发者扩展体验。

- 把采集器契约测试扩展为可选的每日真实源 canary，并明确平台限流状态。
- 建立统一 connector SDK，隔离官方 API、RSS、浏览器采集和私有插件。
- 为 Python/TypeScript SDK 增加分页、重试、超时、类型生成和发布流水线。
- 将前端 1 MB 主包拆分为按领域加载的 vendor chunk，建立 bundle budget。
- 将 5 分钟以上的后端测试拆分为 unit/integration/e2e 并行矩阵。
- 增加示例数据集、示例工作流和从采集到报告的可重复演示。

完成标准：外部源失败不会阻塞主流程；SDK 具备版本兼容测试；首屏资源体积和 CI 时长都有明确预算。

## P2：3-6 个月

目标是强化可观测性、数据治理和可验证 AI 输出。

- OpenTelemetry 覆盖 API、数据库、Redis、采集器、模型调用和异步任务。
- 引入提示词与模型评测基线，追踪引用完整率、拒答准确率和事实风险。
- 完善知识库删除证明、对象存储一致性修复和租户级备份恢复。
- 增加 PostgreSQL/pgvector 的真实性能基线和大规模迁移演练。
- 为 Webhook、SSO、SCIM 和审批执行链增加端到端安全测试。
- 发布数据处理清单、威胁模型和架构决策记录（ADR）。

完成标准：关键链路可追踪、可回放、可解释；隐私删除和恢复目标可自动验证。

## P3：6-12 个月

目标是形成健康的开源生态，而不是继续无边界扩展功能数量。

- 稳定 v1 API 和 SDK 兼容承诺。
- 建立插件签名、能力声明和最小权限沙箱。
- 发布公共路线图、治理规则、维护者职责和版本支持周期。
- 建立匿名、可选的安装健康反馈机制，默认关闭且不上传内容数据。
- 评估国际化、无障碍 WCAG 2.2 AA 和多区域合规需求。

## 明确不做

- 不提供验证码破解、设备指纹伪装或账号权限绕过。
- 不把 LLM 生成内容表述为已经核验的事实。
- 不在默认配置中启用外部写入、高成本模型调用或公开网络监听。
- 不为了阶段编号继续增加缺少用户验证的抽象模块。

## 版本发布建议

首个 GitHub 开源版本建议标记为 `v0.1.0`，并在 Release Notes 中明确“开发者预览”。当 P0 完成、真实源 canary 稳定、认证加固完成后再进入 `v0.2.0`；只有 API、迁移、SDK 和安全响应策略稳定后才考虑 `v1.0.0`。
