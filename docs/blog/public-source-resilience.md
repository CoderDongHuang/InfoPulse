# arXiv 返回 429 之后：公开采集的节流、回退与覆盖语义

更新日期：2026-10-24。[返回主文](./infopulse-open-source-engineering.md) · [专题索引](./README.md)

来源覆盖提醒里出现 `export.arxiv.org/api/query` 的 HTTP 429 时，问题不在页面绘制，也不意味着本机数据库损坏。请求已经抵达一个拒绝继续处理的上游端点。此时采集器需要减少请求，并让使用者知道哪些内容没有更新。

InfoPulse 的处理对象是公开资讯主链。Hacker News、GitHub、DEV、arXiv 与 RSS 的归一化结果进入持久化资讯，再供发现、搜索和工作台读取。微博/B站/贴吧讨论采集有独立的 crawler 与样本链，不能拿公开资讯同步成功证明讨论采集也已可用。

## 限流不能沿用普通故障的快速重试

通用 HTTP 层允许网络或部分 5xx 故障进行有限重试，但遇到 429 会抛出带冷却信息的 `UpstreamRateLimited`。`Retry-After` 既可能是秒数，也可能是 HTTP 日期；缺失、无效、负数或无穷值会采用默认等待值。测试核对一次 429 只产生一次请求，避免一次用户操作立刻扩成多次限流请求。

arXiv 采集器还维护自己的请求状态：

| 机制 | 当前实现 | 目的与边界 |
| --- | --- | --- |
| 互斥与间隔 | 默认按事件循环共享锁，请求至少相隔 3 秒 | 连接测试、手动同步和调度不各自独立突发；测试注入的客户端有独立状态 |
| 成功缓存 | 按请求数量缓存 5 分钟，返回深拷贝 | 合并近期重复读取，调用者修改结果不污染缓存 |
| 端点冷却 | API 与 RSS 分别记录冷却截止时间 | 改变批次大小可以绕过缓存，但不能绕过 API 冷却 |
| 有限回退 | API 失败后尝试官方同分类 RSS | RSS 仍受请求间隔和自己的冷却约束 |

源码位于 [arxiv.py](../../backend/app/services/collectors/arxiv.py) 和 [HTTP 工具](../../backend/app/services/collectors/http.py)。这些状态没有跨进程共享；启动多个 worker 仍会增加上游总流量。实例应明确由哪个 sources worker 负责采集，关闭不需要的 API 内嵌 worker。

## 回退必须保留来源差异

API 按提交时间查询 `cs.AI`、`cs.LG`、`cs.CL`。不可用时尝试 `https://rss.arxiv.org/rss/cs.AI+cs.LG+cs.CL`，读取官方每日发布订阅。二者分类相近，发布时间和内容窗口可能不同，不能把 RSS 解释成 API 的完整等价副本。

归一化不只提取标题和链接，还保留作者、摘要、分类、日期和外部标识。官方 RSS 可能给出无版本链接和带版本 OAI guid；采集器在可匹配时使用版本标识，与 API 身份对齐，减少回退造成的重复入库。原始记录里的 `feed_url` 和后端日志可用于识别实际走了哪条路径。

HTTP 200 也不一定代表有效数据。HTML 错误页、错误 Atom 或不能识别论文的 RSS 会被拒绝；正常的空每日订阅则可以是有效结果。解析器需要区别“今天没有条目”和“根本没有收到订阅内容”。

如果 API 和 RSS 都失败，调用报告无法更新，已有数据库记录仍保留。过期缓存不作为本次同步成功返回。读者仍可能看到旧论文，因此判断新鲜度应查看来源同步时间和状态，不能只看列表是否非空。

## 自动化与现场证据各自回答什么

[故障回归测试](../../backend/tests/test_arxiv_resilience.py)使用 `MockTransport` 和受控时钟，不向 arXiv 制造测试流量。它验证：429 不快速重试、日期解析、RSS 回退、并发缓存、缓存副本、冷却后的恢复、批次间隔、非法响应、版本标识，以及过期缓存不能冒充成功。这里模拟的是协议和状态，不能证明现场网络连通。

2026-10-24 的[Edge 启动验收](../audits/2026-10-24-open-source-readiness.md)则给出了现场证据：API 请求失败后，官方 RSS 于 15:13:56 返回 200，来源中心显示健康。同一轮发现页有 89 条候选内容。这些记录证明当时的回退和展示流程可用，没有证明四个来源永久在线或信息覆盖完整。

## 开发时如何复查

先在来源中心核对时间、错误和其他来源状态。多个来源同时连接失败时检查后端联网、DNS、防火墙和代理环境；只有 arXiv 限流时等待冷却并查看 API/RSS 的日志，不需要删库或更换密钥。

需要手动同步时，在使用同一本地运行目录的 `backend` 终端执行：

```powershell
.\.venv\Scripts\python.exe -m scripts.public_server --sync-once
```

该命令会真实请求所有已启用来源，有来源失败时返回非零，不宜在短时间内反复执行。自动化测试则应使用隔离配置，按[贡献指南](../../CONTRIBUTING.md)运行，避免误读个人配置。更多排查与凭据边界见[配置指南](../29-configuration-guide.md)。

后续若引入跨进程协调、更多数据源或不同缓存策略，还需要验证总请求预算、恢复后的调度、重复身份与数据新鲜度。来源恢复本身不应成为“完整覆盖”的承诺。
