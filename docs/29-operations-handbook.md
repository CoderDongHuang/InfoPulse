# 阶段 29 生产运维手册

## 部署

1. 按 `29-configuration-guide.md` 将密钥写入 Secret 管理器，执行 `python scripts/production_check.py`。
2. 固定镜像 digest，执行供应链扫描和签名验证；数据库必须为 PostgreSQL 16 并启用 pgvector。
3. 先备份并验证可恢复性，再执行 `alembic upgrade head`；独立部署 API、调度、编排和媒体工作进程。
4. 发布到隔离试点，检查 ready/live、指标、告警、审计日志及阶段 20 至 28 浏览器路径。
5. 金丝雀指标在错误预算内才扩大流量；否则立即停止并回滚。

## 升级与回滚

- 升级前保存数据库快照、当前镜像 digest、OpenAPI 快照和配置版本。
- 先升级数据库的向后兼容变更，再部署应用；破坏性 schema 变更必须跨两个版本完成。
- 应用回滚使用上一签名镜像；数据库仅在迁移明确支持且备份已验证时执行 `alembic downgrade <revision>`。
- 回滚后执行租户隔离、财务守恒、连接器幂等和审计链校验，并记录事件时间线。

## 管理员操作

- 每日检查 SLO、错误预算、队列积压、连接器健康、账务差异和安全告警。
- 所有 OAuth 应用、写连接器、密钥租约及高风险行动必须双人审批；禁止审批自己的请求。
- 密钥轮换先建立新租约并验证，再撤销旧租约；不得在日志、工单或数据库明文字段保存密钥。
- 租户导出、删除、驻留迁移和监管撤回均需保留审批及不可变审计记录。

## 支持与事件响应

| 等级 | 示例 | 首次响应 | 行动 |
| --- | --- | --- | --- |
| P0 | 跨租户泄露、资金错误、全局不可用 | 15 分钟 | 启动指挥室、冻结高风险写入、通知安全/财务/合规负责人 |
| P1 | 单区域不可用、支付或 OAuth 大面积失败 | 30 分钟 | 故障转移、供应商升级、每 30 分钟更新状态 |
| P2 | 功能降级、有替代路径 | 4 小时 | 建立缺陷和风险接受期限，进入最近维护版本 |
| P3 | 一般问题或文档缺口 | 1 个工作日 | 排入正常迭代 |

不得在工单中收集密码、令牌、Cookie 或完整个人数据。复盘必须包含影响租户、数据/资金范围、责任链、时间线、根因、补偿和可验证整改项。

## SLO 与灾难恢复

- API 月可用性目标 99.9%，关键写入成功率 99.95%，P95 目标 500ms；超过错误预算时冻结非必要发布。
- 每季度执行多区域、断网、换钥和支付中断演练；每半年执行备份恢复和灾难最小内核演练。
- RPO/RTO、值班表、升级联系人和监管通知期限由部署组织签署并存入受控运行手册，仓库不预填真实联系人。
