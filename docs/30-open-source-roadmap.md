# InfoPulse 开源优化路线图

更新日期：2026-10-09。当前定位是本地开发者预览，不是所有模块正式完工。`[x]` 仅表示下述明确范围完成；`[ ]` 表示待完成。详细问题与测试对应见 [修复验收报告](./audits/2026-10-09-remediation.md)，实验边界见 [能力矩阵](./32-capability-matrix.md)。

## 本轮缺陷收敛

- [x] A01：注册默认非管理员，管理员通过本机命令授予。
- [x] A02/A03：统一出站公网校验、逐跳 DNS 固定、重定向/大小/总预算；安装目标绑定。
- [x] A04/A05：生成必须认证；共享数据源写操作仅系统管理员。
- [x] A06/A07/A08/A09：回执落库、UTC、SSE 单终态、无匹配条件失败，补回归。
- [x] A10/A11：真实 dispatch/outbox、人工/connector 执行与回执、幂等及不确定状态；不承诺任意工具。
- [x] A12：协作生成经过校验的草稿版本，不直接改发布版本。
- [x] 知识任务 lease、重试恢复、staging 先落地、有界上传与状态自动刷新。
- [x] refresh 单次消费、会话撤销、跨 worker 数据库限流、指标默认拒绝。
- [x] API 参数、认证及完整 schema 快照门禁与故障回归。
- [x] 最小依赖入口、本机随机密钥初始化、默认 loopback、WS 代理配置。
- [x] 修复产品验收新增的 multipart 422、工具外键初始化、目录并发唯一键及工具栏换行问题。
- [x] 产品浏览器脚本：7 组检查、36 路由巡检、桌面/移动截图、WS 与会话撤销。

## P0：发布可靠性，下一批

- [x] 最小容器栈真实构建与 Nginx UI/大于 1 MiB 上传/WS 握手；GitHub Linux CI 已通过，见验收报告。
- [ ] 完整 Chromium 采集镜像构建与 browser crawler/media 可选运行依赖验收；不以最小镜像代替。
- [ ] PostgreSQL 降级/升级的数据保留与独立 worker 中断恢复集成矩阵，不能只看 SQLite。
- [x] Linux Python 3.10/3.11 最小安装、pip check、PostgreSQL 迁移往返与产品浏览器 CI；Windows Python 3.10 干净安装本机验证。
- [ ] Windows 持续 CI、多平台版本约束文件和镜像 digest 维护。
- [ ] 所有核心按钮、401/断网/取消/超时、两用户协作、跨租户负向 UI 测试；路由巡检不等于按钮验收。
- [x] 每次 PR 的 npm/pip 漏洞门禁与 Python CycloneDX/JSON artifact；本轮升级旧 setuptools 后通过，零已知漏洞不等于未来为零。
- [ ] 固定可重复 fixture：采集 -> 内容 -> 事件 -> 分析 -> 报告 -> 通知 -> 回执跨域业务验收。

验收：从空库和空缓存启动可重现；容器入口和独立 worker 都可运行；原始故障能由 CI 捕捉；发布证据标明日期和环境。

## P1：结构收敛，1-2 个月

- [ ] crawler/collector 来源契约统一，保留讨论样本与资讯的业务差异，不强行合成巨型服务。
- [ ] 通知、平台 webhook、业务 connector 共用技术投递基础设施，领域授权与回执独立。
- [ ] 严格 DTO/OpenAPI 类型生成，优先清理权限、工作流与知识 API 的高风险 `any`。
- [ ] 按领域拆分大型 Vue 页面、请求状态和 composables，补组件回归。
- [ ] 前端主包约 1 MB 的 bundle budget 与按需依赖加载；不要调高告警阈值冒充优化。
- [ ] 后端测试按 unit/integration/e2e 划分并行矩阵，保持跨数据库回归。
- [ ] SDK 真实 HTTP、分页、重试和版本兼容矩阵及发布流水线。

验收：同一 fixture 重构前后结果、租户边界和副作用一致；包体和 CI 时长有测量预算，不以删测试改善数字。

## P2：真实质量与运行保障，2-6 个月

- [ ] 可选真实源 canary，区分源停机、限流、授权不足和代码回归。
- [ ] 真实 LLM、SMTP、S3、SSO/SCIM、Slack/Teams/飞书/钉钉提供商验收，密钥只通过 secret 注入。
- [ ] 固定模型评测集：引用完整率、无证据拒答、结构正确率、事实风险与失败降级。
- [ ] API/模型/采集/任务/投递的 trace_id、耗时、成本、重试原因和低基数指标。
- [ ] 对象/向量/缓存/备份删除一致性与恢复演练；建立 RPO/RTO 和性能基线。
- [ ] 实验模块 feature flag/插件隔离；只有明确用户需求时开发真实分布式或形式化能力。

验收：能解释结果来源、实际执行、费用和失败点；恢复、删除与权限保证可自动复核；静态规则分数不当作模型质量。

## P3：稳定版与治理

- [ ] v1 API/SDK 支持周期、兼容性声明和发布迁移承诺。
- [ ] 最小权限插件、签名和沙箱，不相信客户端自报审批或 formal_result。
- [ ] ADR、威胁模型、维护者责任与社区治理；国际化、无障碍和合规评估。

## 明确不做

- 不提供验证码破解、权限绕过或未授权私有数据采集。
- 不填虚构凭据、不把生成文字或治理声明包装成已验证事实。
- 不将 `unknown` 投递自动重放，不用“入队成功”替代远端成功。
- 不因阶段编号继续增加缺少实际用户验证的抽象模块。
- 不自动合并未验证的 Dependabot major PR。

建议发布仍使用 `v0.x` 开发者预览；只有核心安装、权限、迁移、外部集成、恢复和兼容性全部通过定义好的验收后，才考虑稳定 v1。
