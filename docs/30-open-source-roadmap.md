- [x] 可选本机真实源 canary：HN/GitHub/DEV/arXiv 及注册→检索→收藏→工作台→日报→站内通知，保留每源结果，见 R21；不依赖实时网络的 CI 仍使用确定性 fixture。
- [ ] 真实源长期可用性监测、错误分类/退避/Retry-After、RSS 实站矩阵及长期质量评估；单次 canary 不等于持续稳定。
- [ ] 真实 LLM、SMTP、S3、SSO/SCIM、Slack/Teams/飞书/钉钉提供商验收，密钥只通过 secret 注入。
- [ ] 固定模型评测集：引用完整率、无证据拒答、结构正确率、事实风险与失败降级。
- [ ] API/模型/采集/任务/投递的 trace_id、耗时、成本、重试原因和低基数指标。
- [ ] 对象/向量/缓存/备份删除一致性与恢复演练；建立 RPO/RTO 和性能基线。
- [ ] 实验模块 feature flag/插件隔离；只有明确用户需求时开发真实分布式或形式化能力。

验收：能解释结果来源、实际执行、费用和失败点；恢复、删除与权限保证可自动复核；静态规则分数不当作模型质量。

## 明确不做

- 不提供验证码破解、权限绕过或未授权私有数据采集。
- 不填虚构凭据、不把生成文字或治理声明包装成已验证事实。
- 不将 `unknown` 投递自动重放，不用“入队成功”替代远端成功。
- 不因阶段编号继续增加缺少实际用户验证的抽象模块。
- 不自动合并未验证的 Dependabot major PR。

建议发布仍使用 `v0.x` beta，并明确公开数据主链与实验模块的区别；只有核心安装、权限、迁移、外部集成、恢复和兼容性全部通过定义好的验收后，才考虑稳定 v1。
