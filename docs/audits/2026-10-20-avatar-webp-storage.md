# R36-A：私有头像 WebP 存储（已完成）

## 验收契约

- [x] 上传接口重新校验非空及 2 MiB 上限，实际解码判断格式，不信任扩展名与 MIME。
- [x] 接收浏览器裁剪的 512 × 512 WebP，服务端处理为 256 × 256 WebP。
- [x] EXIF 方向矫正、移除 EXIF/ICC/XMP 等元数据；限制服务端解码像素，避免绕过前端的过大图片。
- [x] 数据库持久化，提交成功后才返回成功；同账号替换、恢复默认，旧版本失效。
- [x] 鉴权读取且只允许当前账号，禁止匿名和其他账号读取；响应 private/no-store、nosniff。
- [x] 兼容旧数据库中的 PNG 头像，替换后自动使用 WebP，无需批量改写已有数据。
- [x] 增加 Alembic 0036 迁移及 OpenAPI 契约快照。

原图大小不在服务端裁剪前判断：正常界面只发送已经裁剪的成品；API 的 2 MiB 和 1600 万像素限制是对直接调用接口的独立安全边界，不限制用户在浏览器本地选择的大图。

## 部署到本地已有安装

启动前运行 `alembic upgrade head`；项目本地运行脚本会执行迁移。原有账号无需重新注册。新表为 `user_avatars`，备份数据库时一并备份即可，无需开放头像目录到公网。

## 后续边界

头像存储在数据库，适合私人/小型自托管安装。若以后面向大规模多租户服务，可增加对象存储、账户级上传频率限制及网关请求体上限。当前不使用第三方图床，不公开原图。
